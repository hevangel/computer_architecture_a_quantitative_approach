# RAID-6 P/Q and single-symbol correction

**Topic:** Appendix D storage and Chapter 2 symbol-level ECC · **Editions:** 5–7 · **Files:** [SystemVerilog](sv/raid6_p_q_chipkill.sv), [VHDL](vhdl/raid6_p_q_chipkill.vhd)

## Background

RAID-6 uses independent parity equations to reconstruct two known erasures. A separate symbol code can locate one corrupted nibble using two check symbols, illustrating recovery from a failed four-bit DRAM chip. See Hennessy and Patterson, *Computer Architecture: A Quantitative Approach*, 6th edition (2017), Appendix D §D.2 and 7th edition (2025), Chapter 2 §2.2. These are original educational models, not a particular RAID layout or commercial Chipkill code.

## Design

The combinational RAID circuit encodes four data bytes in low-to-high order, followed by P and Q. P is XOR; Q weights bytes by 1, 2, 4 and 8 in GF(256) using polynomial 0x11d. The erasure mask identifies up to two known missing symbols, including parity. The output recomputes parity from recovered data; `recover_valid` only indicates at most two erasures, not integrity of surviving data.

The independent ten-nibble code encodes eight data nibbles and P/Q check nibbles over GF(16), polynomial 0x13, with weights 1 through 2^7. It corrects one unknown-position nonzero nibble corruption, including either check symbol. Position 15 means no error. An unrecognized syndrome deasserts `symbol_valid`; multiple errors can alias a correctable syndrome and require an outer integrity check. Neither block models parity rotation, disk control, latency or production ECC layout.

## Verification

Both testbenches read the same 36 deterministic codewords generated by the independently tested Python reference. For each, they test all 64 erasure masks (22 valid masks with zero, one or two failures) and every position with all 15 nonzero symbol errors, as well as clean words. Both simulations passed at 7776 ns. Python field arithmetic is checked exhaustively against polynomial long division. Verilator lint passed for the RTL.
